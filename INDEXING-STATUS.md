### Gotcha: the bulk endpoint 403s until the key is warm

A bulk `POST https://api.indexnow.org/indexnow` came back
`403 SiteVerificationNotCompleted` even though the key file served 200. A single
URL submitted by GET first returns 200 and completes verification; the bulk POST
then succeeds immediately:

```sh
KEY=8f794212-13e7-4c4c-848a-382bbe6cba7a
curl -s -o /dev/null -w '%{http_code}\n' \
  "https://api.indexnow.org/indexnow?url=https%3A%2F%2Fretrotv.fun%2F&key=$KEY"
```

Re-run the bulk submission after adding a batch of shows — each new show page
and each day's archive page is a new URL.

### Claiming the property

`verification()` in `src/app/layout.tsx` emits the ownership `<meta>` tag for
both consoles from environment variables, so claiming a property needs no code
change:

| Variable | Console | Value to use |
| --- | --- | --- |
| `GOOGLE_SITE_VERIFICATION` | Google Search Console | the `content` value from the "HTML tag" method |
| `BING_SITE_VERIFICATION` | Bing Webmaster Tools | the `content` value of the `msvalidate.01` tag |

Set either with `vercel env add <NAME> production`, redeploy, then press Verify.
A missing variable emits no tag; an empty one would emit a tag that reads as a
failed check.

A Search Console **domain** property (`retrotv.fun`) is the one in use, and it
verifies by DNS only — no meta tag. The record is live at GoDaddy:

```
Type  TXT
Name  @
Value google-site-verification=sdow5OHoGCQzqrGQ3udoQ_Mu7R7XizF8CBvfQSQrcKw
TTL   3600
```

Confirmed resolving on 8.8.8.8, 1.1.1.1, 9.9.9.9 and the authoritative
`ns67.domaincontrol.com`, with no competing TXT record. 8.8.8.8 is the one that
matters — it is what Search Console reads.

A domain property is the better choice here: it covers `www`, bare, http and
https, and every subdomain in one property, where a URL-prefix property would
only cover the exact origin. `GOOGLE_SITE_VERIFICATION` therefore stays unset;
the env var is kept for Bing, which does accept a meta tag when added
standalone. DNS is at GoDaddy (`ns67/ns68.domaincontrol.com`), not Vercel, so
any further records have to be added at the registrar.

## Archive pages carry their answer

Each settled puzzle page server-renders the show, its facts and a link to its
show page, inside a collapsed `<details>` — indexable, but not spoiling anyone
browsing the archive. The `<title>` names the show, because "<show> screenshot
quiz" and "puzzle #N answer" are the queries these pages can win.

`isSettledPuzzleDate()` in `src/lib/rotation.ts` is what holds today's answer
back; `/archive/<today>` is additionally `noindex` because it is the home page's
puzzle at a second URL. Both are covered by tests — do not loosen that guard.

## What is still worth doing, and is not code

1. **Original prose on the show pages.** Every one of the 375 is TMDB's
   overview, median 236 characters, zero original words — the scaled-content
   pattern Google's 2024 core update targeted. Thirty pages written by a person
   beat 375 templated ones. Generating them from a model is the same trap one
   level up.
2. **Directory listings.** Flickle, Episode.wtf and Showsies all have
   alternativeto.net entries that rank for "games like Wordle". Free, and worth
   more than a hundred show pages.
3. **A real link from iusedtowatchthis.com.** It links from the sitewide nav
   menu only. One in-content post is worth considerably more.
